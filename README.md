# Campus Reconnect / 校园网自动重连

Windows 图形界面的 Dr.COM Portal 自动重连工具。支持每日多个时间点、时间段循环检测、跨午夜、托盘运行和登录后自启，并处理休眠恢复与失效会话。

## 下载与使用

从本仓库 **Releases** 下载便携 ZIP，解压到可写目录后运行 `CampusReconnect.exe`。需要 Windows 10/11 和系统自带的 .NET Framework 4.x，无需 Python 或管理员权限。

1. 填写本校认证网址、自己的账号和密码，设置检测时间。
2. 点击“保存设置”，再点击“启动监控”。发布版账号密码为空，监控默认暂停。
3. 可先用“立即检测 / 重连”检查。关闭窗口后继续在托盘运行，右键托盘图标可退出。
4. 需要自启时，勾选“Windows 登录后自动启动”并保存。移动目录后重新保存，以更新启动路径。

`settings.example.xml` 是空白模板，按需复制为 `设置.xml`；也可直接通过界面保存配置。

## 适用范围

适用于采用兼容 Dr.COM Portal 接口的网络。目前支持动态配置中的认证模式 `1` 和 `9`，Portal HTTP/HTTPS 端口分别为 `801` 和 `802`。默认认证地址 `http://10.0.100.3/` 只是可修改的默认值，不是公共服务。其他学校的接口、验证码或附加认证策略可能需要适配。

程序读取网关给出的客户端 IP 与认证配置，按配置生成账号前缀。外网持续失败且认证显示已在线时，会按兼容网页流程尝试清理一次旧会话并重新认证，清理间隔至少 15 分钟。此操作可能注销当前账号并解绑 MAC。

## 定时规则

| 项目 | 示例 | 含义 |
| --- | --- | --- |
| 每日时间 | `07:00,12:30,18:00` | 每个时间点每日执行一次 |
| 检测时间段 | `07:00-12:00,18:00-23:59` | 时间段内循环检测 |
| 跨午夜 | `23:00-07:00` | 当晚到次日早上 |
| 全天 | `00:00-00:00` | 起止相同代表全天 |
| 间隔 | `5` | 每 5 分钟检查 |

默认每天 07:00，并在 07:00–23:59 每 5 分钟检测；只有启用监控后才执行。每日任务允许在目标时间后 10 分钟内补跑。开机和休眠恢复后等待 20 秒，网络任务最多运行 180 秒。界面连续约 75 秒无心跳时，守护进程尝试恢复，10 分钟最多 3 次。

电脑需要开机、登录 Windows 并已连接校园网的 Wi-Fi 或网线。锁屏可运行，关机或休眠期间不执行，不主动开机或唤醒电脑。

## 隐私与网络行为

- 源码、模板及发布包不附带任何真实账号、密码、运行日志或校园网页快照。
- 用户配置保存在 EXE 同目录 `设置.xml`，**密码为明文**。不要上传该文件或带有会话信息的日志。
- 凭据只发往用户填写的认证服务器。HTTP 网关本身不提供传输加密，建议在网关支持时使用 HTTPS。
- 使用微软连接测试文本与华为 HTTPS 204 端点检测外网，任一成功即视为可用；探测不保证所有网站或 VPN 均可访问。
- 请求不使用系统 HTTP 代理，程序不会修改网卡、代理或防火墙配置。

## 从源码构建

在 Windows PowerShell 或 PowerShell 中执行：

```powershell
.\build.ps1 -Test
.\package.ps1
```

使用系统 .NET Framework C# 编译器，无第三方 NuGet 依赖。输出位于 `out/`，发布 ZIP 与 SHA-256 校验值位于 `dist/`。打包使用明确文件清单，不读取工作目录里的个人配置或历史日志。

## 测试与诊断

`build.ps1 -Test` 检查定时逻辑、模拟登录和会话清理、子进程超时及守护行为。测试使用虚构账号和模拟响应，不向真实网关提交登录，也不注销校园网。

| 参数 | 行为 |
| --- | --- |
| `--background` | 托盘启动 |
| `--diagnose` | 检查认证状态与外网 |
| `--portal-info` | 读取实时认证配置 |
| `--self-test` | 本地回归测试，建议使用空白构建目录 |
| `--verify-reconnect` | **真正注销并重登**，仅在允许短暂断网且已配置账号时使用 |

本地测试与 CI 不代表已在所有校园网或所有隔夜场景验证。运行状态写入本机 `运行日志.txt`，诊断信息可能包含 IP，请脱敏后再反馈。
